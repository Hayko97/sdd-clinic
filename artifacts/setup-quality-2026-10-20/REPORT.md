# SDD Clinic setup repair report — 2026-10-20

Implemented on `codex/setup-evidence-quality` in the isolated Clinic worktree. The original Clinic checkout, its running service and the kpcru application/specifications were preserved. This is an upstream setup repair, not a customer-cancellation implementation or a rewrite of previously generated client specs.

## What changed

- Initial evidence selection now interleaves documentation, manifests, tests, data/SQL, UI, services and configuration. It selects complete line ranges beyond import preambles, handles semicolon-free and multiline declarations, and lists omitted ranges within the existing 36,000-character budget.
- Initial/deep/rebuild, reuse-only reruns and product-source setup share a typed quality review. It requires every applicable project area and every qualified scenario, checks source ranges and test references, rejects common scaffolds and generic procedures, and stops when the reviewer identifies a substantive generation defect. Malformed review output gets at most two correction attempts; a semantic blocker is not retried as a request to approve the same deficient specs.
- Concrete validation plans distinguish existing tests, proposed tests and manual checks. Each plan includes prerequisites, fixture values, actions, assertions and expected evidence. Actual execution results remain separate and unverified during setup. Product refinement changes also receive these concrete plans.
- Missing mission, technology, architecture, contracts, UI/UX, operations and roadmap guidance is generated from the review. Existing custom guidance and accepted/pending requirements remain intact. Exact previous design/validation template defaults can upgrade safely; customized templates cannot.
- Setup records source hashes, selected/omitted evidence, generated OpenSpec artifact hashes, the managed CLI version and decisions/gaps in `openspec/project/setup-review.md`. It does not fabricate approval, passing tests or a committed source revision.
- Provider-free repair remains available, but its generated companions are explicitly `[CLINIC:DRAFT]` and `UNVERIFIED / INCOMPLETE`. Additional database/browser test scripts are surfaced with prerequisites to review.

Provider responses in these tests are scripted; they are not live model-quality evidence.

The original audit involved a different eligible-file inventory, so this is not an apples-to-apples recall percentage. ## Remaining limits and integration

- Live Codex/Claude generation against kpcru has not been rerun. The two opt-in live tests remain skipped. Deterministic guards and scripted provider tests prove orchestration and rejection behavior, not universal semantic correctness.
- Initial setup remains sampled. Use deep analysis for complete eligible-text processing; even deep analysis and a separate model review cannot prove semantic completeness or application equivalence.
- Existing custom or stale generated specifications are preserved. They need a reviewed refinement; this fix deliberately does not overwrite kpcru requirements. Customer cancellation remains required and its implementation gap remains open.
- No global installation, package publication, source-branch merge or deployment was performed. This branch is reviewable; the currently installed Clinic continues to run its previous version until integration and installation.
- The current agent reviewed the diff and executed checks. No separate independent QA agent has reviewed this revision, and no target-branch integration has been claimed. The active change remains unarchived.
