## Input and storage
The composer recognizes connection URLs, SSH commands and credential-shaped blocks on paste/change, and also offers an explicit credentials mode. Sensitive input never goes into session storage, transcript/workflow records or provider prompts. A dedicated authenticated POST accepts the transient input, parses locally, validates the selected project agent, and saves profile metadata separately from secrets. Malformed/unsupported input produces a fixed actionable message without echoing credentials. Saving does not initiate a network connection; Test is explicit. The supported formats cover existing PostgreSQL, MySQL/MariaDB, MongoDB and SQLite adapters and SSH/SFTP. Arbitrary prose/unsupported services are rejected rather than sent with secrets to a model.
Profiles have explicit agent IDs. Legacy unassigned profiles remain PO-only. Assignment grants the agent's data tool; MCP checks both project and agent ownership on every operation. Models receive only source IDs/names/type and permitted paths. Developer/QA environments never receive raw credentials. Planning can inspect explicitly assigned sources using read-only broker tools. PO metric prefetch is filtered to the selected agent's assigned sources.
Use the OS keyring when available. In Docker, fall back to AES-256-GCM encrypted per-connection files with a random 32-byte key and private directory/file permissions in the persistent application volume, outside mounted projects. This protects stored files from casual disclosure; it does not isolate the key from a compromised local service or host. If persistence fails, label session-only. Do not claim a successful connection from a successful save. SSH still requires a verified host fingerprint and permitted paths; incomplete access settings are reported inline.
